Developer verification only. These tests do not install or run AI on the VPS.

integration.cjs and example.cjs take the complete merged website tree as their first argument. python_api.py takes the same tree. installer.py expects the original uploaded tree at latest/platform-server-browser-upload beside the build directory; it creates temporary websites and never writes to /var/www.

wasm-inference.cjs requires Node and sharp and takes a JPEG containing a cat as its argument. It executes the actual bundled quantized detector using CPU/WASM, while Node/sharp replaces browser canvas preprocessing. No GPU or native ONNX inference is used. The reference photograph is not included.

Full rendered-browser/camera testing remains a reserve-server acceptance step.

Cumulative revision adds workbench.cjs, which tests named images and the actual Blockly example with mocked camera/inference; dashboard-dom.mjs tests the actual HTML/controls with happy-dom (developer-only dependency), passing the payload/ directory as its first argument. Installer upgrade tests require the previous AI payload under build/previous-ai/payload. These development dependencies are not loaded by the website and do not need to be installed on a user's PC or the VPS.

worker-speed.cjs executes the actual speed-patch worker on CPU/WASM with Node image resizing and a reference photo (first argument). It checks bounded dimensions, repeated inference and timing in all three modes; it writes speed-benchmark.json to the working directory. reference-speed-results.json records one reference-photo run, not device-wide performance or accuracy.

OCR tests: ocr-ui.cjs checks lazy loading, crop/result APIs and cancellation with a host fixture. ocr-example.cjs runs the real five-widget Blockly example. ocr-tabs-dom.mjs requires developer-only happy-dom and checks the actual tabs/crop events. ocr-host-real.cjs uses the bundled browser UMD client and controller with an actual Node/WASM worker adapter (developer-only tesseract.js@7.0.0), including word boxes. It is not a full browser/subworker test. ocr-reference-results.json records clean synthetic printed samples, matched after whitespace normalization; this is not an accuracy/performance guarantee on photos. All language/runtime assets used by the website are served locally from the installed payload. No developer test dependency is needed on users' devices or the VPS.

Accuracy update: ocr-image.cjs checks the actual preprocessing pixels, bounded scaling and bypass. ocr-ui.cjs additionally checks transformed word boxes. ocr-accuracy-reference-results.json records actual WASM tests using the shipped preprocessing on a cropped user photo and the existing clean printed samples. The user photo is deliberately omitted. A close crop and Single line already recovered the photo text without enhancement; this is not evidence that enhancement fixes arbitrary full-scene OCR.

Voice tests: speech-ui.cjs covers consent, lifecycle, exact final matching, consumed queues, bounded audio, worklet/fallback and cleanup. speech-example.cjs runs the paired five-widget archive with the real Blockly runtime. speech-tabs-dom.mjs checks actual HTML with happy-dom. speech-client-real.cjs uses the actual browser client and packaged Vosk worker/WASM; developer prerequisites are fake-indexeddb and the official Vosk test.wav (not bundled), with test paths documented in the script. Reference timings are in speech-reference-results.json. These do not replace physical microphone/browser acceptance tests.

Speech-to-text revision adds transcription-example.cjs (real Blockly), speech-capture.cjs (actual AudioWorklet flush), and transcription-client-real.cjs (actual unrestricted browser-client/WASM in a Node VM). speech-ui.cjs also checks append/clear/finalization with queued replies and separation of partial/final text. Prerequisites for the real engine check match speech-client-real.cjs. See transcription-reference-results.json; the model made errors on part of the recording, so this is not an accuracy benchmark.

TTS revision: tts-ui.cjs simulates the browser native speech API and verifies local-only routing, no remote fallback, async voice discovery/cancellation, validation, microphone interlock, replacement, blocked-gesture recovery and cleanup. tts-example.cjs runs the paired five-widget archive through real Blockly, including the no-local-voice case. tts-tabs-dom.mjs inspects actual HTML with happy-dom. Audible native synthesis is not tested in this container; test local voices on your target browsers/devices.

LLM revision: llm-ui.cjs checks lazy/background generation, streaming, Results progress, warm reuse, bounds, cancellation, stale replies, prepare/error handling and reset. llm-example.cjs runs the real paired five-widget Blockly example; llm-tabs-dom.mjs checks actual HTML with happy-dom. llm-worker-real.cjs runs the actual browser bundle/worker and model through CPU/WASM in Node with a local-only fetch adapter; no npm inference dependency is needed. It uses the supplied payload directory as its first argument and writes a reference JSON in the working directory. llm-reference-135M/360M.json records the limited three-prompt comparison, not an accuracy evaluation. The first model is not shipped. Actual browser/mobile performance remains an acceptance step.

Voice Q&A revision: conversation-ui.cjs checks completed phrases, mic-off ordering, final-answer playback, cancellation in every phase, late events, model failures, missing voices and direct audio unlock. conversation-example.cjs runs the real five-widget Blockly archive; conversation-tabs-dom.mjs checks stable compact panel navigation and manual tool-switch cancellation. python_api.py covers all new bridge functions. Installer tests include ai.9 upgrade with unchanged model inode, small backup and exact rollback. Physical microphone/audible synthesis acceptance remains necessary.
